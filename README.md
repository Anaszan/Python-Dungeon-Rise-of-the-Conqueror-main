# Python Dungeon : Rise of the Conqueror (ดันเจี้ยนแห่งไพทอน : การกำเนิดใหม่ของผู้พิชิต)

เกมผจญภัยดันเจี้ยนมุมมองไอโซเมตริก (isometric dungeon crawler) สร้างด้วย React + Three.js
ผู้เล่นควบคุมตัวละครเดินสำรวจดันเจี้ยน ต่อสู้กับ "อสูรบั๊ก" (Bug Monsters) เก็บไอเทมเสริมพลัง
และมีระบบบัญชีผู้ใช้ / บันทึกความคืบหน้า / กระดานอันดับผ่าน Supabase

> หมายเหตุจากโค้ด: ระบบต่อสู้หลักตอนนี้คือ **Python code sandbox จริง** ([`SpellConsole.tsx`](src/game/SpellConsole.tsx))
> รันด้วย [Pyodide](https://pyodide.org) (CPython คอมไพล์เป็น WASM) — ผู้เล่นเขียนทั้ง **โจมตีปกติและสกิลพิเศษเป็นโค้ด Python จริง**
> คนละกล่อง ปุ่ม "Flee" แบบเดิมยังอยู่เป็นทางเลือกหนี ไม่มีปุ่มกดโจมตี/สกิลตรง ๆ อีกต่อไป เกมมี **6 ด่าน ตรงกับ 6 บทเรียน**
> (ตัวแปร, เงื่อนไข, การวนซ้ำ, ฟังก์ชัน, การจัดการไฟล์, การจัดการข้อผิดพลาด) ก่อนเข้าแต่ละด่านอาจารย์เมอร์ลินจะสอนบทนั้นก่อนเสมอ
> ([`ChapterIntro.tsx`](src/screens/ChapterIntro.tsx)) พร้อมห้องฝึกซ้อม ([`PracticeConsole.tsx`](src/game/PracticeConsole.tsx))
> ให้ลองเขียนโจมตี/สกิลพิเศษใส่หุ่นฝึกซ้อมก่อนเข้าด่านจริงได้ ไม่มีผลกับสถานะตัวจริง ดูรายละเอียด API ที่ผู้เล่นเรียกใช้ได้ในหัวข้อ
> "Python combat sandbox" ด้านล่าง

## เทคโนโลยีที่ใช้

- **React 19** + **TypeScript** + **Vite** — ตัวแอปและ build tooling
- **@react-three/fiber** + **@react-three/drei** + **three.js** — เรนเดอร์ฉาก 3D
- **zustand** — state management (auth store, game store)
- **@supabase/supabase-js** — auth, database (Postgres), และ realtime-ready backend
- **oxlint** — linting


## กติกาเกม

- **เลือกตัวละคร**: หลังล็อกอินครั้งแรกจะเจอหน้าเลือกอาชีพ (นักรบ/นักบวช/นักเวท/โจร) + สีผิว เลือกครั้งเดียวแล้วบันทึกลง
  `game_saves.character_class`/`skin_color` ถาวรต่อบัญชี — ครั้งต่อไปที่ล็อกอินหรือรีเฟรชหน้าเว็บจะข้ามหน้านี้ไปเข้าเกมเลย
- **เลือกระดับความท้าทาย**: หลังสร้างตัวละครเสร็จ (ก่อนเข้าด่านแรก) จะเจอหน้าเลือกโหมด **ง่าย/ยาก** ซึ่งเป็นความยากของ
  *โจทย์โค้ด* ไม่ใช่ของตัวมอนสเตอร์ — เลือกครั้งเดียวแล้วบันทึกลง `game_saves.difficulty` เปลี่ยนทีหลังได้จากเมนูหยุดชั่วคราว
  (ดูหัวข้อ "ระดับความท้าทาย (ง่าย/ยาก)")
- **การเดิน**: WASD หรือลูกศร เดินในดันเจี้ยน ชนกำแพงแล้วเดินผ่านไม่ได้ (แต่ละด่านกำหนดพื้นที่เดินได้ของตัวเองใน `levels.ts`)
- **ก่อนเข้าแต่ละด่าน**: เจอหน้า ChapterIntro เสมอ — อาจารย์เมอร์ลินสอนบทเรียนของด่านนั้น (ตัวแปร/เงื่อนไข/ลูป/ฟังก์ชัน/ไฟล์/error
  handling) พร้อมตารางคำศัพท์สั้น ๆ ตามด้วย **ตัวอย่างคาถา** — โค้ด Python ที่สมบูรณ์และรันได้จริงพร้อมคอมเมนต์บอกผลลัพธ์
  ให้ดูก่อนลงมือเขียนเอง ถัดลงมาเป็น **ลิงก์อ่านเพิ่มเติม** ไปหน้าของบทนั้นบน
  [W3Schools Python](https://www.w3schools.com/python/default.asp) (`readMore` ใน `lessons.ts` บทละ 2-4 ลิงก์
  เปิดแท็บใหม่เสมอ) สำหรับคนที่อยากได้คำอธิบายเต็มกว่าที่เกมสอน จากนั้นมี **ห้องฝึกซ้อม (PracticeConsole)** ให้ลองเขียนโจมตี/สกิลพิเศษใส่ "หุ่นฝึกซ้อม" จริงก่อนกดเข้าด่าน
  — หุ่นฝึกซ้อมแยกจากมอนสเตอร์จริงทั้งหมด ไม่มีคูลดาวน์ ลองพังกี่ครั้งก็ได้ และมีปุ่ม "ฝึกใหม่ (สุ่มโจทย์)" ให้สุ่มโจทย์แบบอื่นมาลอง
  ในด่านที่มีหลาย variant (ดูรายละเอียดเนื้อหาที่ `src/game/lessons.ts`)
- **การต่อสู้** (แนว Ragnarok — สู้กันตรงที่เจอ ไม่มีการตัดฉากไปไหนทั้งสิ้น ดูหัวข้อ "ระบบต่อสู้ในฉาก"):
  - **คลิกที่มอนสเตอร์เพื่อล็อกเป้า** (หรือกด Tab วนเป้าที่อยู่ใกล้) แล้วแผงคาถาจะลอยขึ้นข้าง ๆ มันในฉากเลย — ฉาก 3D
    ยังเดินต่อไปทั้งหมด: เดินได้, มอนตัวอื่นยังอยู่, เวลาไม่หยุด
  - มอนสเตอร์ยืนอยู่กับที่ แต่ **ตีเมื่อเราเข้าไปใกล้** (ในระยะ `MONSTER_AGGRO_RANGE`) เป็นจังหวะตาม `attackInterval`
    ของมันเอง — เดินถอยออกมาให้พ้นระยะก็หยุดตี และจังหวะตีจะเริ่มนับใหม่หมดเมื่อกลับเข้าไป
  - เดินเข้าไปกลางฝูงพร้อมกันหลายตัว = โดนตีพร้อมกันหลายชุด
  - ผู้เล่นเขียนโค้ด **Python จริง** ใน SpellConsole 2 กล่องแยกกัน — กล่อง **"โจมตี"** เรียก `attack(amount)` และกล่อง
    **"สกิลพิเศษ"** เรียก `skill(amount)` — ทั้งสองต้องเขียนโค้ดเอง ไม่มีปุ่มกดโจมตีตรง ๆ อีกแล้ว (ดูหัวข้อ "Python combat sandbox")
  - โจทย์ที่ได้ในแต่ละกล่องขึ้นกับโหมดที่เลือกไว้: **โหมดง่าย** ได้โค้ดตั้งต้นแบบ "เติมคำในช่องว่าง" (มี `___` ให้เติม) ตามบทเรียน
    ของด่านนั้น ส่วน **โหมดยาก** ได้ "โจทย์ของมอนสเตอร์" กับกล่องเปล่า ต้องเขียนเองทั้งหมด (ดูหัวข้อถัดไป)
  - **ทั้งสองกล่องมีคูลดาวน์ของตัวเอง** หลังร่ายสำเร็จ (คือหลังโค้ดเรียก `attack(...)`/`skill(...)` จริง ไม่ใช่แค่กดปุ่มรัน) —
    โจมตีปกติพัก 3 วินาที (`ATTACK_COOLDOWN_SECONDS`), สกิลพิเศษพัก 8 วินาที (`SKILL_COOLDOWN_SECONDS`) ทั้งคู่อยู่ใน
    `constants.ts` ปุ่มจะขึ้นนับถอยหลังและกดไม่ได้จนกว่าจะหมดคูลดาวน์ — คูลดาวน์สกิลพิเศษนับถอยหลังตลอดเวลาแม้ไม่ได้ต่อสู้ และ
    ค่าที่เหลืออยู่จะถูกเก็บข้ามด่าน/ข้ามเซสชัน ส่วนคูลดาวน์โจมตีปกติเป็นค่าชั่วคราวไม่ persist ข้ามเซสชัน (สั้นพอที่รีเซ็ตตอน
    รีเฟรชหน้าเว็บได้โดยไม่ต้องเพิ่มคอลัมน์ฐานข้อมูลใหม่)
  - ตอนคาถาออก **ตัวละครจะร่ายท่าของอาชีพตัวเอง** (นักรบฟันดาบ / โจรแทง / นักเวทผลักไม้เท้า / นักบวชชูมือ) พร้อมแสงและ
    วงเวทสีประจำอาชีพ — ดูหัวข้อ "ท่าร่ายคาถาแยกตามอาชีพ"
  - **คาถายิงได้ไกลกว่าที่มันตีถึง** (`SPELL_CAST_RANGE` = 6.5 ช่อง เทียบกับระยะตีของมอน 2.2 ช่อง) — ถอยออกมาแล้วยิงต่อ
    จึงเป็นกลยุทธ์จริง ไม่ใช่บั๊ก ถ้าไกลเกินไปแผงจะบอกระยะปัจจุบันและปุ่มร่ายจะกดไม่ได้
  - ไม่มีปุ่ม **Flee** อีกแล้ว — เดินหนีได้เลยตลอดเวลา กด **Esc** (หรือปุ่ม ✕ บนแผง) เพื่อปลดล็อกเป้า และเลือดของมอนที่ตี
    ไว้ค้างไว้ตรงนั้น กลับมาสู้ต่อทีหลังได้
  - HP ผู้เล่นหมด → เกมโอเวอร์ (แต่ progress ที่บันทึกไว้ยังอยู่ รวมถึงด่านปัจจุบัน)
- **ไอเทม**: เดินเก็บของ heal (ฟื้น HP) หรือ attack (เพิ่มพลังโจมตี) ที่วางอยู่ในดันเจี้ยน — ผู้เล่นเริ่มเกมด้วยพลังโจมตี
  `BASE_ATTACK_POWER = 30` และไอเทมเพิ่มพลังทุกชิ้นทุกด่านให้ `ATTACK_PICKUP_AMOUNT = 10` เท่ากันหมด (ทั้งสองค่าอยู่ใน
  `constants.ts`) เส้นพลังจึงเป็น 30 + 10 ต่อขวดที่เก็บได้เสมอ ซึ่งเป็นฐานที่ใช้ตั้งค่า HP ของบอสแต่ละด่าน
- **ด่าน (levels)**: เกมมี **6 ด่าน ตรงกับ 6 บทเรียน** นิยามอยู่ใน `src/game/levels.ts` (เนื้อหาบทเรียนคู่กันอยู่ใน `lessons.ts`)
  - **ด่าน 1 — ทางเดินมืด** (บทที่ 2: ตัวแปร) — Goblin/Wraith จบด้วย Dragon รวม 9 มอนสเตอร์
  - **ด่าน 2 — ห้องใต้ดินที่ลึกกว่าเดิม** (บทที่ 3: เงื่อนไข) — Goblin Warrior/Orc/Specter/Wraith Elite + ห้องลับ (vault)
    จบด้วยบอส Bone Tyrant รวม 10 มอนสเตอร์
  - **ด่าน 3 — สนามประลองคอมโบ** (บทที่ 4: การวนซ้ำ) — Imp/Goblin Raider/Banshee จบด้วยบอส Hydra รวม 9 มอนสเตอร์
  - **ด่าน 4 — หอคาถาต้องมนตร์** (บทที่ 5: ฟังก์ชัน) — Arcane Wisp/Cultist/Hex Sprite/Spell Knight + ห้องลับ จบด้วยบอส
    Archmage รวม 10 มอนสเตอร์
  - **ด่าน 5 — หอสมุดลับ** (บทที่ 6: การจัดการไฟล์) — Book Golem/Archivist/Ghost Librarian จบด้วยบอส Forbidden Tome
    รวม 9 มอนสเตอร์
  - **ด่าน 6 — ดันเจี้ยนกับดักมรณะ** (บทที่ 7: การจัดการข้อผิดพลาด, ด่านสุดท้าย) — มอนสเตอร์ทุกตัวมี `armor: 0` (เกราะถูกสาป)
    บังคับให้ต้องใช้ `try/except` กันหารด้วยศูนย์ จบด้วยบอส Glitch Wyrm รวม 10 มอนสเตอร์
  - ด่าน 3-6 ใช้ผังดันเจี้ยน (regions/walls) ชุดเดียวกับด่าน 1 หรือด่าน 2 ซ้ำ — ดูเหตุผลเรื่องความเสี่ยงของผังใหม่ในคอมเมนต์
    เหนือ `LEVEL_3_REGIONS` ใน `levels.ts`
  - กำจัดมอนสเตอร์ลูกน้องครบ → **บอสประจำด่านจึงจะปรากฏตัว** (ดูหัวข้อ "บอสประจำด่าน") ล้มบอสแล้ว **ข้ามไปด่านถัดไปทันที**
    (ผ่าน ChapterIntro ของด่านใหม่ก่อน) โดย **HP ผู้เล่น, attack power, และ cooldown สกิลพิเศษที่เหลือจะติดตัวไปด้วย**
    (ไม่รีเซ็ต) ผู้เล่นจะเกิดใหม่ที่จุดเริ่มต้นของด่านใหม่
- **ชนะ**: ล้มบอสของด่านสุดท้าย (Glitch Wyrm) → ส่งคะแนนรวมทั้งเกมขึ้นกระดานอันดับอัตโนมัติ แล้วเข้าหน้า Victory ทันที

## ระดับความท้าทาย (ง่าย/ยาก)

`src/game/difficulty.ts` + `src/game/trials.ts` + `src/screens/DifficultySelect.tsx` — ผู้เล่นเลือกโหมดหลังสร้างตัวละคร
เสร็จและก่อนเข้า ChapterIntro ของด่านแรก (ลำดับหน้าจออยู่ใน `App.tsx`) **ทั้งสองโหมดใช้มอนสเตอร์ HP ดาเมจ คูลดาวน์ ไอเทม
และบอสชุดเดียวกันทุกอย่าง** — ไม่มีอะไรในไฟล์ `levels.ts`/`constants.ts` อ่านค่า difficulty เลย สิ่งที่ต่างกันคือ
"โจทย์โค้ด" ที่กล่องโจมตี/สกิลพิเศษขอจากผู้เล่นเท่านั้น

| | โหมดง่าย (`'easy'`) | โหมดยาก (`'hard'`) |
|---|---|---|
| กล่องเขียนโค้ด | โค้ดอ่านอย่างเดียว + ช่องกรอกตรงที่เป็น `___` (`blanks.ts` + `FillInCode`) | ช่องเขียนเปล่าหนึ่งช่องต่อโจทย์หนึ่งข้อ เขียนเองทั้งหมด (`slots.ts` + `WriteInSlots`) |
| โจทย์ | อยู่ในคอมเมนต์ `# TODO:` ข้างช่องว่าง | เป็นป้ายกำกับของช่องที่ตอบมันโดยตรง + แผง `TrialBrief` เหนือกล่อง (ชื่อโจทย์ + เช็กลิสต์ + ปุ่มคำใบ้) |
| เงื่อนไขก่อนร่าย | ไม่มี — รันโค้ดอะไรก็ได้ | ต้องผ่าน `checks` ของโจทย์ให้ครบก่อน ไม่งั้นคาถา **ร่ายไม่ออก** |
| มอนสเตอร์แต่ละตัว | สุ่ม variant ของ skeleton (บทที่ 2 มี 3 แบบ) | ได้ **โจทย์คนละข้อ** ตาม `pickVariant(monsterId)` |
| ห้องฝึกซ้อม / บอส | เหมือนเดิม | ห้องฝึกซ้อมใช้โจทย์แบบเดียวกัน ส่วนบอสใช้โจทย์เหมือนมอนสเตอร์ตัวอื่นในด่าน |

- **โจทย์ (`TrialSpec`)** หนึ่งข้อประกอบด้วยชื่อโจทย์, `brief` (สิ่งที่มอนสเตอร์เรียกร้อง), `checks` (regex ที่ตรวจซอร์สโค้ด
) และ `hints` — เก็บแยกตามบท (chapter 2-7) กล่องละหลายแบบใน `trials.ts`
- **การตรวจเกิดขึ้น *ก่อน* รันโค้ด**: `SpellConsole.run()` เทียบ `checks` กับซอร์สก่อน แล้วจึงส่งเข้า Pyodide — โค้ดที่ไม่ใช้
  ไวยากรณ์ของบทนั้นจึงไม่มีทางสร้างดาเมจ และเพราะ "ยังไม่ได้ร่าย" จริง ๆ ก็**ไม่เสียคูลดาวน์**ด้วย
- **คอมเมนต์ไม่นับ**: `stripComments()` ตัดคอมเมนต์ทิ้งก่อนตรวจทุกครั้ง ไม่งั้นคอมเมนต์โจทย์ที่แถมมาในกล่อง (ซึ่งมีคำว่า
  `print()`, `attack(...)` อยู่) จะติ๊กเช็กลิสต์ของตัวเองครบตั้งแต่ยังไม่ได้พิมพ์อะไร
- **ช่องเขียนไม่ใช่ด่านกั้น**: `composeSlots()` เอาคำตอบทุกช่องมาต่อเป็นซอร์สก้อนเดียว (โจทย์เป็นคอมเมนต์ + โค้ดใต้ข้อนั้น)
  แล้ว `checks` ก็ตรวจซอร์สนั้นทั้งก้อน — เขียนคาถาทั้งหมดไว้ช่องเดียวแล้วปล่อยช่องที่เหลือว่างก็ผ่านได้
  ช่องจึงเป็นตัวช่วย "บอกว่าข้อไหนอยู่ตรงไหน" ไม่ใช่กฎว่าต้องพิมพ์ลงช่องไหน
- **เปลี่ยนโหมดกลางเกมได้** จากเมนูหยุดชั่วคราว — ไม่รีเซ็ตอะไรทั้งนั้น กล่องโค้ดจะโหลดโจทย์ชุดใหม่ให้ในการ render ถัดไป
- `trials.test.ts` เก็บ **เฉลยอ้างอิงของทุกโจทย์** ไว้ (นอก bundle เพราะห้ามส่งเฉลยถึงผู้เล่น) และบังคับว่า
  ทุกบทต้องมีโจทย์ครบทั้งสองกล่อง, regex ต้องไม่เป็น global, และ **คอมเมนต์ตั้งต้นเพียงอย่างเดียวต้องไม่ผ่านโจทย์**

## บอสประจำด่าน (boss)

`monsters.ts` `boss: true` + `bossOf` / `bossIsSealed` / `availableMonsters` ใน `levels.ts` — **แทนที่ "บทสอบจบด่าน" เดิม
ทั้งหมด** (ประตูที่ต้องเขียนโค้ดใหม่หมดถูกลบทิ้งแล้ว พร้อมกับ phase `'exam'` และ `LevelExamOverlay.tsx`)

- ทุกด่านมีบอส **1 ตัวเท่านั้น** (levels.test.ts บังคับ): Dragon → Bone Tyrant → Hydra → Archmage → Forbidden Tome →
  Glitch Wyrm
- **บอสถูกผนึกไว้จนกว่ามอนสเตอร์ตัวอื่นในด่านจะตายครบ** — ระหว่างนั้นบอส **ไม่ถูกวาดในฉากเลย** คลิกไม่ได้ Tab ไม่ติด
  auto-lock ไม่จับ และตีผู้เล่นไม่ได้ เดินไปมุมที่บอสอยู่ก็จะเจอห้องว่าง
- ทุกจุดที่ต้องรู้เรื่องผนึกอ่านผ่าน `availableMonsters()` ตัวเดียวกันหมด (GameScene วาด, CombatTicker ตีกลับ/auto-lock,
  GameScene Tab cycle, store.setTarget) จึงเป็นไปไม่ได้ที่ที่หนึ่งเห็นบอสแต่อีกที่ไม่เห็น
- **ล้มบอส = จบด่านทันที** `store.damageMonster` ขยับ `currentLevel` ในจังหวะเดียวกับหมัดสุดท้าย (ด่าน 6 ไปหน้า Victory
  พร้อมส่งคะแนนขึ้นกระดานอันดับ) แล้ว App จะพาไป ChapterIntro ของด่านใหม่ — **HP, attack power, cooldown สกิลติดตัวไปด้วย**
  เหมือนที่เคยผ่านประตูเดิม
- แถบมุมจอ (`LevelBanner`) นับเฉพาะ **มอนสเตอร์ลูกน้อง** และเปลี่ยนเป็นชื่อบอสสีแดงเมื่อผนึกแตก — ไม่งั้น "8/9 แต่หาตัวสุดท้าย
  ไม่เจอ" จะอ่านเหมือนเกมบั๊ก
- **การสู้กับบอสไม่เหมือนมอนสเตอร์ทั่วไป** — `bossTrial()` ใน `trials.ts` คือโจทย์ของประตูเดิมที่ยกมาทั้งดุ้น (brief + checks +
  คำใบ้ของแต่ละบท): กล่องโค้ด **ว่างเปล่าทั้งสองกล่อง** ต้องเขียนคาถาของบทนั้นเองทั้งหมด มีเช็กลิสต์ติ๊กสดและปุ่มขอคำใบ้
  **บังคับทั้งสองโหมด** (โหมดง่ายก็ไม่มีช่องว่างให้เติมตอนสู้บอส) แต่ละกล่องบวกเงื่อนไขของตัวเองเข้าไปอีกข้อ (กล่องโจมตีต้องเรียก
  `attack(...)` กล่องสกิลต้องเรียก `skill(...)`) จะได้ไม่มีกล่องไหนถูกปล่อยว่าง
- **คัตซีนตอนบอสปรากฏตัว** (`screens/BossIntro.tsx`) — หมัดที่เคลียร์ด่านจะตั้ง `store.bossReveal` ทำให้จอขึ้นแถบดำบน-ล่าง
  โชว์รูปกับชื่อบอส ~4 วินาที ระหว่างนั้น **ผู้เล่นเดินไม่ได้และมอนสเตอร์ตีไม่ได้** (Player/CombatTicker มองว่าเหมือนหยุดเกม)
  กดปุ่มหรือแตะเพื่อข้ามได้ และไม่ถูก persist ลงฐานข้อมูล (รีเฟรชกลางคัตซีน = ข้ามไปเลย)
- เนื้อหาบทเรียนที่เคยใช้เฉพาะบทสอบ (`ExamSpec`, `guardianHp`) ถูกลบออกจาก `lessons.ts` แล้ว ส่วน `ExamCheck` เปลี่ยนชื่อเป็น
  `CodeCheck` เพราะตอนนี้ใช้กับโจทย์ของบอสและโหมดยาก (`trials.ts`) เท่านั้น

## เดินด้วยการคลิก (click to walk)

`clickMove.ts` + `Ground.tsx onFloorClick` + `Player.tsx` — คลิกพื้นตรงไหน ตัวละครเดินไปตรงนั้น ใช้ร่วมกับ WASD/จอยสติ๊กได้

- คลิกพื้น = ตั้งจุดหมาย, คลิกมอนสเตอร์ = เลือกเป้า (Monster.tsx `stopPropagation` ไว้ก่อนถึงพื้น) ทั้งสองอย่างจึงไม่ตีกัน
- เดินด้วยระบบชนเดิมทุกอย่าง — ชนกำแพง/ของตกแต่งแล้วไถลไปตามขอบ ถ้าติดจนขยับไม่ได้ทั้งสองแกนจะ **ยกเลิกการเดินเอง**
  (ไม่มี pathfinding: เดินเป็นเส้นตรง + ไถล ซึ่งพอสำหรับผังทางเดินของเกมนี้)
- กด WASD หรือขยับจอยเมื่อไหร่ = ยกเลิกจุดหมายทันที คนบังคับเองชนะเสมอ
- มีวงแหวนสีทองหมุน ๆ ตรงจุดที่คลิกไว้จนกว่าจะถึง, ยกเลิกอัตโนมัติเมื่อเปลี่ยนด่าน/ตาย และคลิกตอนหยุดเกม/ตายแล้วไม่ถูกจดจำไว้

## ท่าร่ายคาถาแยกตามอาชีพ

`src/character/cast.ts` + `src/character/CastAura.tsx` — ทุกอาชีพโจมตีด้วยการเขียน Python เหมือนกัน แต่ **ถืออาวุธคนละอย่าง**
ท่าร่ายจึงเป็นท่าของอาวุธที่ถืออยู่จริง ไม่ใช่ท่าร่ายเวทแบบเดียวกันหมด

| อาชีพ | ท่า | ยาว | สีเวท |
|---|---|---|---|
| นักรบ | เงื้อดาบขึ้นเหนือหัว บิดไหล่ตาม แล้วฟันลง | 0.80s | ทอง-ส้ม `#ffb454` |
| โจร | ดึงมีดกลับข้างเอว แล้วแทงพุ่งไปข้างหน้า (เร็วที่สุดในสี่อาชีพ) | 0.55s | เขียว `#7de3a4` |
| นักเวท | ยกไม้เท้าขึ้นเหนือหัวจนลูกแก้วอยู่สูงสุด แล้วผลักไปข้างหน้า | 0.85s | ม่วง `#9b82ff` |
| นักบวช | ชูสองมือขึ้นฟ้า เงยหน้า แล้วดึงแสงลงมาดันออกไป (ช้าและกว้างที่สุด) | 0.95s | ทองอ่อน `#ffe07a` |

- **ร่ายตอนไหน**: ตอนที่คาถา "ออก" จริง ๆ — คือหลังโค้ดเรียก `attack(...)`/`skill(...)` สำเร็จ (`onAttackCast`/`onSkillCast`
  ใน TargetPanel) ท่ากับดาเมจจึงลงพร้อมกัน และ**คาถาที่ยังทำโจทย์ไม่ครบจะไม่มีท่าเลย** เพราะยังไม่ได้ร่าย
- **สกิลพิเศษ = ท่าเดิมแต่ใหญ่กว่า**: กว้างขึ้น ~15% ยาวขึ้น ~12% และวงเวท/แสงใหญ่ขึ้น 1.7 เท่า (`SKILL_POSE_GAIN`,
  `SKILL_TIME_GAIN` และ `gain` ใน CastAura)
- **เอฟเฟกต์**: แสงกลมเล็ก ๆ ที่หน้ามือถืออาวุธ + จุดไฟสั้น ๆ ที่ส่องตัวผู้เล่น + **วงเวทบนพื้นใต้เท้า** ที่แผ่ออกแล้วจางหาย
  ทั้งหมดใช้สีของอาชีพ (`CAST_STYLES[cls].color`) — ดันเจี้ยนมืดและกล้องอยู่ไกล ท่าอย่างเดียวจึงมองพลาดได้ง่าย แสงคือสิ่งที่ทำให้
  รู้ว่า "ร่ายออกแล้ว" จากอีกฝั่งห้อง

**สองริกต้องทำคนละแบบ** (เหตุผลเดียวกับ `gait.ts`)

- **โมเดลผู้หญิง** (Quaternius women pack) มีคลิปอนิเมชันมาให้ 24 คลิป — ท่าร่ายจึงเลือกใช้คลิปที่มีอยู่แล้วเล่นครั้งเดียว:
  นักรบ `Sword_Slash`, โจร `Punch_Right`, นักเวท `Gun_Shoot` (ท่าเล็งไปข้างหน้า ใช้กับไม้เท้าได้พอดี), นักบวช `Interact`
  (ท่ายื่นมือออกไป — เป็นตัวที่ใกล้ "ประทานพร" ที่สุดในชุดที่มี) ทุกคลิปถูกปรับ timeScale ให้ยาวเท่ากับค่าของอาชีพนั้น
  **ชายกับหญิงอาชีพเดียวกันจึงร่ายจบพร้อมกันเสมอ** แม้คลิปต้นฉบับจะยาวไม่เท่ากัน (Sword_Slash 1.29s, Gun_Shoot 0.75s)
- **โมเดลผู้ชาย** (rig จาก .obj ด้วย `tools/rig_male.py`) ไม่มีคลิปเลย — ท่าร่ายจึงเป็น **คีย์เฟรมที่จัดท่ากระดูกเองในโค้ด**
  (`CAST_STYLES[cls].pose`) แล้ว interpolate ด้วย smoothstep

**กับดักที่ต้องรู้ถ้าจะแก้ท่าเพิ่ม**

- ท่าร่ายของฝั่งจัดท่าเองต้อง **ซ้อนทับท่าเดิน** ไม่ใช่แทนที่ (ร่ายไปเดินไปได้) การซ้อนตัดสินกัน **รายแกน** ไม่ใช่รายกระดูก:
  แกนที่ท่าเดินเขียนทับทุกเฟรมอยู่แล้ว (`GAIT_DRIVEN_AXES` ใน `gait.ts`) ใช้ `+=` ได้ ส่วนแกนที่ไม่มีใครเขียน **ต้องเขียนจาก
  ท่าพัก (rest) ใหม่ทุกเฟรม** — ถ้าเผลอ `+=` ใส่แกนที่ไม่มีใครรีเซ็ต ค่าจะสะสมทุกเฟรมจนแขนหมุนหลุดออกจากตัว (บั๊กนี้เกิดจริง
  ตอนทำ และเงียบมาก) `applyCastAxis()` คือบรรทัดเดียวที่ตัดสินเรื่องนี้ และ `cast.test.ts` ล็อกพฤติกรรมไว้แล้ว
- **ลำดับ hook สำคัญ**: ใน `CharacterModel` ต้องเรียก `useClipGait`/`useProceduralGait` **ก่อน** `useClipCast`/
  `useProceduralCast` เสมอ เพราะ react-three-fiber รัน frame callback ตามลำดับที่ subscribe — สลับเมื่อไหร่ ท่าเดินจะเขียนทับ
  ท่าร่ายทันที
- ฝั่งคลิปใช้ `AnimationMixer` **คนละตัว** กับท่าเดิน และ **ต้อง `action.stop()` เมื่อจบ** ไม่ใช่แค่ `fadeOut` — action ที่ยัง
  ค้างอยู่ที่ weight 0 จะดัน bind pose ทับกระดูกทุกเฟรม ทำให้ท่าเดินค้างแข็ง
- วงเวทบนพื้นวางที่ y ≈ -0.57 ของกลุ่มผู้เล่น (ซึ่งลอยอยู่ 0.6 เหนือพื้น) ต่ำกว่านี้แล้วพื้นจะบังทั้งวง และใช้ alpha blending
  ธรรมดา ไม่ใช่ additive — พื้นดันเจี้ยนสว่างเป็นสีส้มจากคบไฟอยู่แล้ว บวกสีทองเข้าไปอีกจะมองไม่เห็นอะไรเลย

## ระบบต่อสู้ในฉาก (แนว Ragnarok)

ตั้งแต่ 2026-09-03 การต่อสู้ **เกิดขึ้นในดันเจี้ยนตรงจุดที่เจอกัน** ไม่มีหน้าจอต่อสู้แยก ไม่มีการตัดฉาก และไม่มี phase
`'combat'` อีกต่อไป — ทุกอย่างเกิดใน `'exploring'` ทั้งหมด สิ่งที่เคยเป็น "เข้าสู่การต่อสู้" ตอนนี้คือ **การล็อกเป้า**
(`store.targetId`) เท่านั้น

**วงจรการเล่นหนึ่งรอบ**

1. เดินเข้าไปในด่านตามปกติ — ป้ายชื่อของมอนสเตอร์จะโผล่ให้เห็นเมื่อเข้าใกล้พอ (9 ช่อง ซึ่งอยู่ในระยะไฟตะเกียงพอดี)
2. **คลิกที่ตัวมอน** (หรือ **Tab** เพื่อวนเป้าที่อยู่ในระยะ เรียงจากใกล้ไปไกล) → วงแหวนทองปรากฏใต้เท้ามัน และ
   **แผงคาถาลอยขึ้นข้าง ๆ ตัวมันในฉาก**
3. เขียน Python ในกล่อง "โจมตี"/"สกิลพิเศษ" เหมือนเดิมทุกอย่าง → กดร่าย → เลขดาเมจเด้งขึ้นเหนือหัวมอนตรงนั้น
4. ระหว่างนั้นมอนที่อยู่ในระยะจะตีเราเป็นจังหวะ (หลอดสีแดงใต้ป้ายชื่อคือจังหวะตีของมัน) — จะยืนสู้ หรือถอยออกมายิงไกล
   หรือเดินหนีไปเลยก็ได้ **ทุกอย่างทำได้ตลอดเวลาโดยไม่ต้องปิดแผง**
5. มอนตาย → เป้าปลดเอง แผงปิดเอง เดินไปหาตัวถัดไปได้ทันที (ไม่มีปุ่ม Continue อีกแล้ว)

**ระยะทั้งสี่** (ทุกค่าอยู่ใน `constants.ts` วัดบนพื้นแบบ XZ เท่านั้น ความสูงไม่เกี่ยว)

| ค่า | ระยะ | ความหมาย |
|---|---|---|
| `MONSTER_AGGRO_RANGE` | 2.2 | มอนเริ่มตีเราเมื่อเข้ามาใกล้เท่านี้ ออกไปพ้นก็หยุดตี |
| `SPELL_CAST_RANGE` | 6.5 | คาถาไปถึง — ไกลกว่านี้แผงจะบอกระยะและร่ายไม่ได้ |
| `TARGET_LOCK_RANGE` | 10 | คลิก/Tab ล็อกเป้าได้ไกลสุดเท่านี้ (เล็งเป้าถัดไปข้ามห้องได้) |
| `TARGET_DROP_RANGE` | 13 | เดินหนีไกลกว่านี้แล้วเป้าหลุดเอง |

ลำดับ `AGGRO < CAST < LOCK < DROP` เป็นสิ่งที่ระบบพึ่งอยู่จริง ๆ และมีเทสต์ล็อกไว้ใน `combat.test.ts` — ถ้าคาถายิงได้
ไม่ไกลกว่าระยะตีของมอน "ถอยออกมายิง" จะกลายเป็นทำไม่ได้ทันที

**ล็อกเป้าอัตโนมัติ (และการปิดมัน)** — ถ้าโดนตีอยู่ทั้งที่ยังไม่ได้เลือกเป้า `CombatTicker` จะล็อกตัวที่ใกล้ที่สุดให้เอง
เพื่อไม่ให้ต้องคลิกก่อนจึงจะตอบโต้ได้ แต่ถ้าผู้เล่น **กด Esc / ปุ่ม ✕ เอง** จะตั้ง `suppressAutoTarget` ไว้ ทำให้ระบบ
ไม่ยัดเป้าเดิมกลับมาในเฟรมถัดไปทั้ง ๆ ที่ยังยืนอยู่ในระยะมันตี — ธงนี้จะปลดเองเมื่อเดินออกมาจนไม่มีอะไรตีเราแล้ว หรือเมื่อ
ผู้เล่นเลือกเป้าใหม่ด้วยตัวเอง

**คีย์ที่ใช้ระหว่างสู้** — `WASD`/ลูกศร เดิน · คลิก เลือกเป้า · `Tab` วนเป้า · `Esc` ปลดเป้า (ถ้าไม่มีเป้าอยู่แล้ว `Esc`
จะเป็นการหยุดเกมชั่วคราวเหมือนเดิม) · `Tab` ในกล่องโค้ดยังเป็นการเยื้องบรรทัดตามปกติ

> **หมายเหตุสำคัญ**: เพราะกล่องโค้ดอยู่ *ในฉาก* แล้ว การพิมพ์กับการเดินจึงใช้ปุ่มชุดเดียวกัน — `isTypingTarget()` ใน
> `useKeyboardMap.ts` เป็นตัวกันไม่ให้การพิมพ์คำว่า `while` พาตัวละครเดินชนกำแพง ทุก global key listener ในเกมต้องเรียก
> ตัวนี้ก่อนเสมอ

**เรื่อง UI ที่ต้องรู้เวลาแก้ต่อ**

- แผงคาถา/ป้ายชื่อ/เลขดาเมจ ทั้งหมดวาดด้วย `<Html>` ของ drei ซึ่งอยู่ **ข้างใน `<Canvas>`** เพราะทุกอันยึดกับพิกัดในโลก
- prop `pointerEvents` ของ drei ใช้ได้เฉพาะโหมด `transform` เท่านั้น — ป้ายชื่อกับเลขดาเมจจึงกัน pointer ด้วยคลาส
  `.nameplate-wrapper { pointer-events: none }` แทน (CSS `pointer-events` เป็น inherited property จึงตกถึงลูกทั้งหมด)
- แผงจะ **สลับไปอยู่ทางซ้ายของมอน** เองเมื่อเป้าอยู่ครึ่งขวาของจอ (คำนวณด้วย `Vector3.project()` ในทุกเฟรม + hysteresis
  0.1 กันกระพริบ) — บนจอแคบกว่า 640px แผงจะเลิกยึดกับมอนแล้วไปแปะขอบล่างแทน (media query ใน `index.css` ทับ inline style
  ที่ drei เขียนใหม่ทุกเฟรมด้วย `!important`)
- `monsterSwing` ใน store ถูก push แค่ 10 ครั้ง/วินาที และเฉพาะตอนที่ค่าที่ *แสดงผล* เปลี่ยนจริง — ไม่ใช่ทุกเฟรม

`SpellConsole.tsx` มีกล่องโค้ด 2 กล่องต่อการต่อสู้ (โจมตี, สกิลพิเศษ) แต่ละกล่องรันโค้ดของผู้เล่นผ่าน `pyodideRuntime.ts`
เมื่อกดปุ่มรันของกล่องนั้น (`castSpell()`) โดยจะตั้งค่าตัวแปร/ฟังก์ชันต่อไปนี้ให้อยู่ใน global scope ของ Python **ใหม่ทุกครั้ง**
ก่อนรันโค้ด (สะท้อนสถานะการต่อสู้ล่าสุดเสมอ) — ทั้งสองกล่องได้ชุด global เดียวกัน ไม่ได้แยกสิทธิ์กัน:

| ชื่อ | ชนิด | ความหมาย |
|---|---|---|
| `hp` | int | HP ปัจจุบันของผู้เล่น |
| `atk` | int | พลังโจมตีปัจจุบันของผู้เล่น (`attackPower` ใน store) |
| `monster_hp` | int | HP ปัจจุบันของมอนสเตอร์ที่ล็อกเป้าอยู่ |
| `monster_name` | str | ชื่อมอนสเตอร์ |
| `monster_armor` | int | ค่าเกราะของมอนสเตอร์ (`MonsterData.armor`) — ปกติ default 999 ถ้าไม่ตั้งค่าไว้ ด่าน 6 ตั้งเป็น 0 ทุกตัวเพื่อบังคับบทเรียน try/except |
| `attack(amount)` | function | ลด HP มอนสเตอร์ลง `amount` หน่วยทันที (เรียก `store.damageMonster` ตรง ๆ) — ปัดเป็นจำนวนเต็มและ clamp ไม่ให้ติดลบ; ถ้าเรียกอย่างน้อยหนึ่งครั้ง จะเริ่มคูลดาวน์โจมตีปกติให้อัตโนมัติหลังคาถาทำงานจบ (`SpellResult.attackUsed` → `store.startAttackCooldown()`) |
| `skill(amount)` | function | เหมือน `attack()` แต่ยิงผ่าน `onSkillDamage`; ถ้าเรียกอย่างน้อยหนึ่งครั้งในคาถานั้น ระบบจะเริ่มคูลดาวน์สกิลพิเศษให้อัตโนมัติหลังคาถาทำงานจบ (`SpellResult.skillUsed` → `store.startSkillCooldown()`) |

`attack()`/`skill()` ทำงานเหมือนกันทุกอย่างยกเว้นคูลดาวน์ที่เริ่มคนละตัว — โค้ดในกล่องไหนก็เรียกอีกฟังก์ชันได้ ไม่ได้ล็อกไว้ว่า
กล่องโจมตีต้องเรียกแค่ `attack()` เท่านั้น (การแยกกล่องเป็นเรื่องจัดระเบียบ UI/บทเรียน ไม่ใช่ sandbox boundary ทางเทคนิค)

**โจทย์ตั้งต้นแบบสุ่มในด่าน 1:** `lessons.ts` เก็บโจทย์ตั้งต้นเป็น `attackSkeletons`/`skillSkeletons` (array แทนที่จะเป็น
string เดียว) ด่าน 1 มี 3 แบบต่อกล่อง สลับกันระหว่าง "เติมตัวเลข" กับ "เติมชื่อตัวแปร" — เลือกแบบไหนคำนวณจาก
`pickSkeleton()` (แฮชค่าคงที่จาก monster id ไม่ใช่ `Math.random()`) ทำให้มอนสเตอร์ตัวเดิมได้โจทย์แบบเดิมเสมอ (เสถียรไม่เปลี่ยน
ถ้า component re-render) แต่มอนสเตอร์ 9 ตัวในด่าน 1 จะสลับกันเจอโจทย์คนละแบบไปเรื่อย ๆ ตามธรรมชาติ ด่านอื่นยังมีแค่ 1 แบบต่อกล่อง
(ใส่ใน array ที่มีสมาชิกเดียว) — จะเพิ่ม variant ให้ด่านอื่นในอนาคตก็ทำตามรูปแบบเดียวกันได้เลย

`print()` ในโค้ดผู้เล่นจะถูกจับผ่าน `pyodide.setStdout` แล้วแสดงใน spell log ใต้กล่องโค้ดของตัวเอง ส่วน Python exception จริง
(`NameError`, `TypeError`, `ZeroDivisionError`, `SyntaxError`, `IndentationError`, `ValueError`, `IndexError`, `KeyError`,
`AttributeError`, `FileNotFoundError`) จะถูกจับใน `castSpell()` แล้วแปลเป็นข้อความแนวเวทมนตร์ภาษาไทย (ดู `ERROR_FLAVOR` ใน
`pyodideRuntime.ts`) แทนการโชว์ traceback ดิบ — โจทย์ตั้งต้นทุกด่านเป็นแบบเติมคำในช่องว่าง (`___`) ตั้งใจปล่อยให้รันไม่ผ่านจน
กว่าจะเติมครบ ซึ่งจะโชว์เป็น `SyntaxError` ที่อธิบายไว้แล้วพอดี

Pyodide โหลดแบบ lazy จาก jsdelivr CDN (`https://cdn.jsdelivr.net/pyodide/v0.28.3/full/`) ตอนเข้าห้องต่อสู้ครั้งแรกของเซสชัน
(ไม่ได้ bundle มากับแอป เพราะ asset ของ Pyodide หนักหลาย MB) แล้ว cache ไว้เป็น singleton ตลอดเซสชัน (ทั้งสองกล่องใช้อินสแตนซ์
เดียวกัน) — ต้องมีอินเทอร์เน็ตตอนเข้าเกมครั้งแรกที่จะสู้

**ความปลอดภัยจาก infinite loop:** โค้ดผู้เล่นรันบน main thread แบบ synchronous — ยังไม่มี Web Worker/hard timeout ที่กันได้
ทุกกรณี (เช่น `while True: pass` ที่ไม่เรียก attack()/skill() เลยจะยังค้างทั้งแท็บ) มีแค่ตัวนับเรียก `attack()`/`skill()` ใน
`pyodideRuntime.ts` (`MAX_SPELL_CALLS = 200` ต่อการรัน 1 ครั้ง) ที่ตัดคาถาทิ้งถ้าเรียกถี่เกินไป — ครอบคลุมรูปแบบลูปพังที่บท
การวนซ้ำ (ด่าน 3) ชวนให้เขียนโดยตรง (`while` ที่เงื่อนไขไม่มีวันเป็นเท็จแล้วยิงสกิลรัว ๆ) แต่ไม่ใช่ตัวป้องกันแบบครอบคลุมทุก
กรณี — ควรทำ Web Worker + timeout จริงก่อนเปิดให้ผู้เล่นทั่วไปเล่น

**ขอบเขตตอนนี้ / สิ่งที่ยังไม่ได้ทำ:**
- **โหมดง่าย**: โจทย์ตั้งต้น (skeleton) เป็นแบบ "เติมคำในช่องว่างเดียว" และไม่มีการตรวจว่าคำตอบใช้ concept ของบทนั้นจริงหรือไม่ —
  ผู้เล่นที่เขียน Python เป็นอยู่แล้วลบโจทย์ทิ้งแล้วเขียนเองแบบไม่ใช้ไวยากรณ์ของบทนั้นก็ยังชนะได้ (เช่น ไม่ใช้ if/else ในด่าน 2)
  เป็นข้อจำกัดที่ยอมรับได้สำหรับโหมดสำหรับผู้เริ่มต้น — **โหมดยาก** ปิดช่องนี้ด้วย `checks` ที่ตรวจซอร์สก่อนร่ายทุกครั้ง
  (ดูหัวข้อ "ระดับความท้าทาย")
- การตรวจในโหมดยากเป็น regex บนซอร์สโค้ด ไม่ใช่การวิเคราะห์ AST — ตรวจได้ว่า "มีไวยากรณ์นั้นอยู่จริง" แต่ไม่ได้พิสูจน์ว่า
  ตรรกะถูกต้อง (เช่น มี `try/except` จริงแต่ except ว่างเปล่า ก็ยังผ่าน checks ได้ ถ้าดาเมจถึงเกณฑ์)
- Pyodide รองรับ virtual filesystem จริง (`open()`/`write()`/`read()` ในด่าน 5 ทำงานได้จริงและข้อมูลจะอยู่ข้ามการรันภายในเซสชัน
  เดียวกัน) แต่ไม่ persist ข้ามการรีเฟรชหน้าเว็บ
- ค่าความยากของแต่ละด่าน (`maxHp`/`attackDamage`/`attackInterval` ใน `levels.ts`) เป็นตัวเลขที่ประมาณไว้ตามลำดับความยากที่ควร
  จะเพิ่มขึ้น ยังไม่ได้ผ่านการเล่นจริงเพื่อจูนสมดุล — ควร playtest แล้วปรับตัวเลขตามที่รู้สึกจริงระหว่างเล่น

## ระบบแอดมิน (admin)

`supabase/migrations/20250101000012_admin.sql` + `src/admin/` — บัญชีที่อยู่ใน allow-list จะได้เครื่องมือเพิ่มมา 2 อย่าง

- **วาร์ปข้ามด่าน**: กระโดดไปเริ่มด่านไหนก็ได้ทันที (`store.warpToLevel`) โดย **ไม่ล้างอะไรเลย** — HP, พลังโจมตี, มอนสเตอร์ที่ปราบ
  แล้ว และไอเทมที่เก็บแล้วติดตัวไปหมด วาร์ปกลับมาที่เดิมสถานะก็เหมือนเดิมเป๊ะ ถ้าด่านปลายทางถูกเคลียร์หมดแล้วจะพาไป
  ห้องว่าง ๆ (ปกติเล่นไปตามเกมจะไม่มีวันเจอ เพราะจบด่าน = ข้ามไปด่านถัดไปทันที) วาร์ปไม่ได้ตอนตัวละครตายอยู่
  (ต้องกดเริ่มใหม่ก่อน) และ level ถูก clamp ไว้ที่ 1..6 เสมอ
- **รีเซ็ตมอนสเตอร์รายด่าน**: ปุ่ม "♻ รีเซ็ตมอนสเตอร์" บนการ์ดของแต่ละด่าน (`store.resetLevelMonsters`) ปลุกมอนสเตอร์ทั้งด่าน
  กลับมาพร้อมล้าง HP ที่ค้างไว้ บอสกลับไปถูกผนึกเอง (เพราะผนึกคำนวณจาก "ใครตายแล้ว" ไม่ได้เก็บสถานะแยก) และถ้ากำลังล็อกบอสอยู่
  จะปลดล็อกให้ — **มีผลเฉพาะเซฟของบัญชีแอดมินเอง** ไม่แตะของคนอื่น และไม่คืนไอเทมที่เก็บไปแล้ว (กันฟาร์มพลัง)
- **แดชบอร์ดผู้เล่น**: ตารางเซฟของผู้เล่นทุกคน — ชื่อ/อีเมล/ด่านปัจจุบัน/โหมดความยาก/HP/ATK/จำนวนมอนสเตอร์ที่ปราบ/ไอเทม/
  สถานะพิชิตเกม/เวลาอัปเดตล่าสุด เรียงตามคนที่เล่นล่าสุด
- **เข้าได้ 2 ทาง**: ปุ่มลอย 🛡 มุมซ้ายล่าง และเมนูหยุดชั่วคราว (โผล่เฉพาะแอดมิน) — แผงจะเรนเดอร์ที่ระดับ `App.tsx` จึงเปิดได้ทั้ง
  ตอนอยู่หน้า ChapterIntro และตอนอยู่ในดันเจี้ยน

### จัดการผู้ใช้ (migration 014)

ครบทั้ง 4 อย่างตามข้อกำหนด — **เพิ่ม / แก้ไข / ลบ / ระงับ** อยู่ในส่วน "จัดการผู้ใช้" ของแผงแอดมิน แต่ละปุ่มเรียก RPC ที่ตรวจ
`is_admin()` ในฐานข้อมูลเอง

| การกระทำ | ฟังก์ชัน | หมายเหตุ |
|---|---|---|
| **เพิ่ม** | `admin_create_player(email, password, display_name, nickname)` | สร้างบัญชีแบบยืนยันอีเมลแล้ว ล็อกอินได้ทันที รหัสผ่านขั้นต่ำ 8 ตัว |
| **แก้ไข** | `admin_update_player(...)` | ชื่อที่แสดง/ชื่อเล่น/ชื่อตัวละคร + ด่าน/HP/พลังโจมตี — ช่องที่ส่ง `null` มาจะไม่ถูกแตะ |
| **ลบ** | `admin_delete_player(user_id)` | ลบ `auth.users` แล้ว cascade ทั้ง profiles / game_saves / user_contacts / scores · ลบตัวเองไม่ได้ |
| **ระงับ** | `admin_set_suspended(user_id, boolean, reason)` | ตั้ง `profiles.suspended_at` + เหตุผล · ระงับตัวเองไม่ได้ |
| (เสริม) สิทธิ์แอดมิน | `admin_set_admin(email, boolean)` | เพิ่ม/ถอดแถวใน `admin_emails` จากหน้าเว็บ · ถอดสิทธิ์ตัวเองไม่ได้ |
| (เสริม) รีเซ็ตรหัสผ่าน | `supabase.auth.resetPasswordForEmail` | ส่งลิงก์ไปที่อีเมลผู้เล่น แอดมินไม่เห็นรหัสผ่านใหม่ |

**"ระงับ" มีผลจริงที่ฐานข้อมูล ไม่ใช่แค่ซ่อน UI** — RLS ของ `game_saves` ถูกแยกเป็น select/insert/update/delete โดยฝั่งเขียน
ทั้งหมดมีเงื่อนไข `not is_suspended(auth.uid())` เพิ่มเข้าไป (รวมถึง `scores` และการแก้ `profiles` ของตัวเอง) ผู้ถูกระงับยัง
**อ่าน**เซฟตัวเองได้ เพื่อให้เกมรู้ว่าเขาเป็นใครแล้วขึ้นหน้า `SuspendedScreen` แทนดันเจี้ยน ถึงจะแก้ JavaScript ในเบราว์เซอร์ก็เขียน
อะไรไม่ได้สักแถว

**ข้อควรรู้เรื่อง `admin_create_player`**: มันเขียนลงตาราง `auth.users` / `auth.identities` ของ GoTrue ตรง ๆ (ใช้ `pgcrypto`
แฮชรหัสผ่าน) ซึ่ง Supabase ไม่ได้รับรองอย่างเป็นทางการ — เลือกทางนี้เพราะทางที่ถูกต้องกว่าต้องใช้ `service_role` key ซึ่ง
**ห้ามฝังในหน้าเว็บเด็ดขาด** ถ้าวันหนึ่ง Supabase เปลี่ยนโครงตารางจนฟังก์ชันนี้พัง ทางแก้คือย้าย**เฉพาะฟังก์ชันนี้**ไปเป็น Edge
Function ที่เรียก `auth.admin.createUser` ส่วนที่เหลือในไฟล์ไม่ต้องแก้

**เรื่องความปลอดภัย** — จุดที่ตัดสินว่าใครเป็นแอดมินอยู่ที่ฐานข้อมูล ไม่ใช่ที่ client:

- allow-list เป็นตาราง `public.admin_emails` ที่ **เปิด RLS แต่ไม่มี policy เลย** → client ปกติอ่านไม่ได้เลย เข้าถึงได้เฉพาะ
  ผ่านฟังก์ชัน SECURITY DEFINER เท่านั้น (เหตุผลที่ไม่ใช้คอลัมน์ `is_admin` บน `profiles`: ตารางนั้นทุกคนอ่านได้ เพราะกระดาน
  อันดับต้องใช้ — ใส่ไปก็เท่ากับประกาศให้รู้ทั่วกันว่าใครเป็นแอดมิน)
- `get_admin_player_overview()` **ตรวจ `is_admin()` ในตัวมันเอง** และ `raise exception` (42501 → HTTP 403) ถ้าไม่ใช่แอดมิน —
  การซ่อนปุ่มฝั่ง client เป็นแค่เรื่องความสวยงาม ไม่ใช่ปราการ
- ปุ่มวาร์ปแก้ได้แค่เซฟ **ของบัญชีตัวเอง** (เรียก action ตัวเดียวกับที่เกมใช้อยู่แล้ว) ต่อให้มีคนแฮ็ก `isAdmin` ใน devtools ก็ได้
  แค่ปุ่มวาร์ปเซฟตัวเอง ส่วนแดชบอร์ดจะได้ 403 กลับมา
- **เพิ่มแอดมินคนใหม่**: `insert into public.admin_emails (email) values ('someone@example.com') on conflict do nothing;`
  (เทียบอีเมลแบบไม่สนตัวพิมพ์เล็ก/ใหญ่) — ถ้ายังไม่ได้รัน migration นี้ `is_admin()` จะไม่มีอยู่ ซึ่ง `adminApi` ตีความว่า
  "โปรเจกต์นี้ไม่มีระบบแอดมิน" แล้วซ่อน UI ทั้งหมดไปเงียบ ๆ

| ตาราง | หน้าที่ |
|---|---|
| `profiles` | หนึ่งแถวต่อผู้ใช้ที่ล็อกอิน (สร้างอัตโนมัติผ่าน trigger เมื่อสมัคร), เก็บ `display_name` และ `nickname` (unique, public เหมือน display_name), อ่านได้ทุกคน (ใช้โชว์กระดานอันดับ/ล็อกอินด้วยชื่อเล่น), แก้ได้เฉพาะเจ้าของ |
| `user_contacts` | หนึ่งแถวต่อผู้ใช้ เก็บ `phone` (unique) — **ไม่ public**, อ่าน/เขียนได้เฉพาะเจ้าของแถวเท่านั้น (RLS) |
| `game_saves` | เซฟเกม 1 ช่องต่อผู้ใช้: มอนสเตอร์/ไอเทมที่เก็บแล้ว, HP, attack power, ด่านปัจจุบัน (`current_level`), cooldown สกิลพิเศษ (`skill_cooldown`), อาชีพ/สีผิวที่เลือก (`character_class`/`skin_color`), ระดับความท้าทายของโค้ดที่เลือก (`difficulty`) — เจ้าของเท่านั้นที่อ่าน/เขียนได้ (RLS) |
| `scores` | ประวัติการพิชิตเกม (จำนวนมอนสเตอร์ที่กำจัดได้ + เวลา) อ่านได้ทุกคน, เพิ่มได้เฉพาะเจ้าของแถว |
| `admin_emails` | allow-list อีเมลของแอดมิน — เปิด RLS โดยไม่มี policy เลย จึงอ่านไม่ได้จาก client เข้าถึงผ่าน `is_admin()` / `get_admin_player_overview()` (SECURITY DEFINER) เท่านั้น |

Auth ใช้ Supabase Auth แบบอีเมล/รหัสผ่าน (`supabase.auth.signInWithPassword` / `signUp`) ผ่าน `src/auth/authStore.ts`
session จะถูก sync อัตโนมัติผ่าน `onAuthStateChange`

**ล็อกอินด้วยเบอร์โทร/ชื่อเล่น**: Supabase Auth ผูกบัญชีกับอีเมลเป็นหลักเสมอ ตอนสมัครผู้เล่นต้องกรอกอีเมล+เบอร์โทร+ชื่อเล่นครบ
ตอนล็อกอินกรอกได้ช่องเดียว (อีเมล/เบอร์โทร/ชื่อเล่น) — ถ้าไม่ใช่รูปแบบอีเมล ฝั่ง client จะเรียก RPC function
`resolve_login_email` (นิยามใน `migrations/20250101000004_phone_nickname_login.sql`) เพื่อหาอีเมลจริงจากชื่อเล่น/เบอร์โทรก่อน แล้วค่อยเรียก
`signInWithPassword` ตามปกติ ปุ่มออกจากระบบอยู่ที่ `LogoutButton.tsx` มุมบนขวาระหว่างเล่นเกม

## การตั้งค่าและรันโปรเจกต์

### แบบที่ 1 — Supabase บนเครื่องตัวเอง (ต้องมี Docker) ← แนะนำสำหรับการตรวจงาน

```bash
npm install
npm run local:up     # ยก Supabase ขึ้นด้วย Docker + เขียน .env.local ให้เอง
npm run dev          # http://localhost:5173
```

ได้ฐานข้อมูลเปล่า ๆ ที่รัน migrations ครบ พร้อมบัญชีตัวอย่าง 5 บัญชี (แอดมิน / ผู้เล่นสามระดับ /
ผู้ถูกระงับ) รายละเอียดทั้งหมด — ต้องลงอะไรก่อน, เปิด Studio/Mailpit ที่ไหน, รหัสผ่านของบัญชีตัวอย่าง,
วิธีพิสูจน์ว่า RLS กันจริง — อยู่ที่ [`supabase/README.md`](supabase/README.md)

### แบบที่ 2 — โปรเจกต์ Supabase บนคลาวด์

1. คัดลอก `.env.example` เป็น `.env` แล้วใส่ค่าโปรเจกต์ Supabase:
   ```
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_ANON_KEY=your-anon-key
   ```
2. เอาไฟล์ใน `supabase/migrations/` ไปวางใน Supabase SQL Editor ทีละไฟล์ **เรียงตามชื่อ** (ไฟล์ท้าย ๆ ที่ยังไม่รันจะทำให้บางฟีเจอร์ degrade อย่างสุภาพแทนที่จะพัง — ดูคอมเมนต์ใน `persistence.ts`)
3. ติดตั้ง dependencies และรัน dev server:
   ```
   npm install
   npm run dev
   ```

### 2026-07-12 — Phase 3: Python combat sandbox (MVP → เต็มรูปแบบ 6 ด่าน)

ก่อนหน้านี้ระบบต่อสู้เป็นปุ่มกด Attack/สกิลพิเศษ/Flee ธรรมดา วันนี้แทนที่ด้วยระบบเขียนโค้ด Python จริงทั้งหมด แบ่งเป็น 2 รอบ:

**รอบแรก (MVP):**
- เพิ่ม Python code sandbox รันด้วย [Pyodide](https://pyodide.org) จริง (`pyodideRuntime.ts`, `pyodide.d.ts`) โหลดแบบ lazy จาก CDN
- สร้าง `SpellConsole.tsx` แทนปุ่ม Attack เดิม: เขียนโค้ด → กด "ร่ายคาถา" → รันใส่มอนสเตอร์จริง พร้อม battle API เบื้องต้น (`hp`, `atk`, `monster_hp`, `monster_name`, `attack()`)
- แปล Python exception เป็นข้อความแนวเวทมนตร์ภาษาไทยแทน traceback ดิบ
- โจทย์ตั้งต้นสอนตัวแปร + if/else (บทที่ 2-3) แบบโค้ดสำเร็จรูป

**รอบสอง (ขยายเต็มรูปแบบ ตามที่ขอเพิ่ม):**
- แยก SpellConsole เป็น **2 กล่องโค้ดอิสระ** — โจมตี (`attack()`) และสกิลพิเศษ (`skill()`) ต้องเขียนโค้ดทั้งคู่ ไม่มีปุ่มกดตรง ๆ อีกแล้ว (เอาปุ่มสกิลพิเศษแบบเดิมออก, เปลี่ยน store action `useSkill` → `startSkillCooldown` ที่ทำงานเมื่อโค้ดเรียก `skill()` จริง)
- โจทย์ตั้งต้นเปลี่ยนเป็นแบบ **เติมคำในช่องว่าง** (`___`) ทุกด่าน แทนโค้ดสำเร็จรูป
- เพิ่ม `lessons.ts`: เนื้อหาบทเรียน + ตารางคำศัพท์ + โจทย์ทั้ง 6 บท (ตัวแปร, เงื่อนไข, การวนซ้ำ, ฟังก์ชัน, การจัดการไฟล์, การจัดการข้อผิดพลาด)
- เพิ่ม `ChapterIntro.tsx`: หน้าสอนของอาจารย์เมอร์ลินก่อนเข้าทุกด่าน (wire ผ่าน `App.tsx` ให้โผล่ทุกครั้งที่ `currentLevel` เปลี่ยน)

- เพิ่ม field `armor` ใน `MonsterData` และ global `monster_armor` ใน battle API สำหรับบทเรียนข้อผิดพลาด
- เพิ่มตัวกัน infinite loop เบื้องต้น (`MAX_SPELL_CALLS` ใน `pyodideRuntime.ts`) เพราะด่าน 3 สอนการวนซ้ำโดยตรงแล้ว
- อัปเดต README ทั้งหมดให้ตรงกับโครงสร้างใหม่ (ดูหัวข้อ "Python combat sandbox" และ "กติกาเกม" ด้านบน)

**ยังไม่ได้ทำ/ยังไม่ได้ตรวจสอบ** (ดูรายละเอียดเพิ่มในหัวข้อ "Python combat sandbox" และ "สถานะปัจจุบัน" ด้านบน): ด่าน 3-6 ยังไม่เคยเดินสำรวจจริงในเบราว์เซอร์, ตัวเลขความยากยังไม่ผ่าน playtest, ยังไม่มี Web Worker/timeout กัน infinite loop แบบครอบคลุมทุกกรณี
